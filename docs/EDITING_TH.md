# คู่มือแก้เว็บไซต์ฉบับสั้น

**เพิ่มหรือแก้ข้อมูลภายหลังได้ครับ ไม่ต้องเริ่มทำเว็บใหม่** เว็บนี้เป็นไฟล์ HTML/CSS ธรรมดา ไม่มีระบบฐานข้อมูลหรือขั้นตอน build สำหรับเว็บ การแก้ข้อความเล็กน้อยทำผ่านหน้า GitHub ได้ ส่วนการเปลี่ยนรูปแบบหรือเพิ่มส่วนใหม่ให้ช่วยแก้และตรวจบนมือถือได้

## แก้ตรงไหน

| สิ่งที่ต้องการเปลี่ยน | ไฟล์ |
| --- | --- |
| ข้อความภาษาไทย | docs/index.html |
| ข้อความภาษาอังกฤษ | docs/en/index.html |
| แรงบันดาลใจ | ค้นหา CONTENT: story ใน HTML ทั้งสองภาษา |
| บทความเรื่องจุดเริ่มต้น | docs/articles/inspiration.html และ docs/en/articles/inspiration.html |
| บทความก่อนเผยแพร่ | docs/articles/before-a-release.html และ docs/en/articles/before-a-release.html |
| การ์ดบทความบนหน้าหลัก | ค้นหา CONTENT: journal ใน HTML หน้าหลักทั้งสองภาษา |
| รูปเมนูและคำบรรยาย | ค้นหา CONTENT: gallery ในหน้าหลักทั้งสองภาษา รูปอยู่ docs/assets/menu-photos/ |
| ช่องทางผู้พัฒนา | ค้นหา CONTENT: creator ในหน้าหลักทั้งสองภาษา |
| สี ขนาดตัวหนังสือ ระยะห่างและหน้าตา | docs/assets/site.css |
| ไอคอนเว็บ | docs/assets/icon.svg |

ข้อความทั่วไปอยู่ระหว่างแท็ก เช่น `<p>ข้อความที่อ่านบนเว็บ</p>` แก้เฉพาะข้อความข้างใน เก็บ `<p>` และ `</p>` ไว้ ลิงก์มีรูปแบบ `<a href="ที่อยู่ลิงก์">ข้อความลิงก์</a>` ถ้าข้อความมี `&` ให้เขียนเป็น `&amp;` และอย่าใส่ `<` เป็นตัวอักษรโดยไม่ escape

## แก้ผ่านหน้า GitHub

1. เปิด repository eos_rom_mlv_modifly และเลือก branch `site/eos-600d-bilingual`
2. เปิดโฟลเดอร์ docs แล้วเลือก index.html สำหรับภาษาไทย หรือ en/index.html สำหรับภาษาอังกฤษ
3. กดไอคอนดินสอ / Edit this file หากคุณมีสิทธิ์แก้
4. ค้นหาข้อความหรือคำว่า CONTENT: story แล้วแก้ข้อความ โดยเก็บแท็ก HTML ไว้
5. กด Commit changes ใส่ชื่อสั้น ๆ ว่าแก้อะไร เช่น “ปรับเรื่องราวแรงบันดาลใจภาษาไทย” แล้วบันทึกลง branch นี้
6. แก้อีกภาษาให้สื่อความหมายสอดคล้องกัน ไม่จำเป็นต้องแปลคำต่อคำ
7. ตรวจหน้าเว็บภาษาไทย/อังกฤษบนมือถือและคอมพิวเตอร์ หากเปิด Pages แล้ว ให้รอ deployment สำเร็จและรีเฟรชเว็บ การ commit อย่างเดียวไม่ได้แปลว่า deploy สำเร็จเสมอ

**ผู้ดูแลแจ้งว่าเปิด GitHub Pages แล้ว** เมื่อ Pages ใช้ branch นี้และโฟลเดอร์ /docs การแก้ไขที่บันทึกลง branch นี้จะถูกนำไปอัปเดตเว็บเมื่อ deployment สำเร็จ ไม่ต้องสร้าง firmware release ใหม่เพื่อแก้ข้อความบนเว็บ

## หากอยากให้ช่วยแก้

บอกได้เป็นภาษาปกติ เช่น “เพิ่มเรื่องเบื้องหลังการทำเมนูไทย” หรือ “แก้สถานะเป็นผลทดสอบที่ผมส่งให้วันนี้” จะช่วยเรียบเรียงไทย–อังกฤษ แก้ไฟล์ ตรวจหน้าจอ แล้วบันทึกเวอร์ชันให้

การปรับโครงสร้างเมนูเว็บหรือเพิ่มหน้าใหม่ต้องแก้ HTML/CSS มากกว่าการเปลี่ยนข้อความเล็กน้อย แต่ไม่ต้องเขียนระบบใหม่ทั้งหมด Git เก็บประวัติไว้ให้ตรวจและย้อนการแก้ไขได้

## แนวทางเขียนบทความ

ใช้ [CONTENT_STYLE.md](CONTENT_STYLE.md) เป็นแนวทางทั้งภาษาไทยและอังกฤษ เน้นสุภาพ เป็นกันเอง และเล่าจากข้อมูลจริง ภาษาไทยใช้ “เรา” เรียกโครงการและ “คุณ” เรียกผู้อ่าน เติม “ครับ” เป็นบางจุดอย่างเป็นธรรมชาติ ส่วนภาษาอังกฤษใช้ “we” และ “you” โดยเรียบเรียงใหม่ให้ลื่นไหล ไม่ต้องแปลคำต่อคำ

ในหน้าบทความ ค้นหา `CONTENT: article-body` เพื่อแก้เนื้อหา หากเปลี่ยนชื่อเรื่องหรือคำโปรย ให้ปรับ `<title>`, meta description, Open Graph และการ์ดบนหน้าหลักของทั้งสองภาษาด้วย วันที่ในบทความใช้ `<time datetime="YYYY-MM-DD">วันที่ที่อ่านง่าย</time>` และควรเปลี่ยนเมื่อแก้เนื้อหาจริง

หากเพิ่มบทความ ให้สร้างไฟล์ชื่อเดียวกันใน `docs/articles/` และ `docs/en/articles/` แล้วตรวจว่าปุ่มสลับภาษาเปิดบทความเรื่องเดียวกัน เพิ่มการ์ดในหน้าหลักทั้งสองภาษา และตรวจลิงก์กับหน้าจอมือถือก่อนบันทึก

## ก่อนเปลี่ยนข้อมูลที่มีผลต่อผู้ใช้

- สถานะการทดสอบ: ใช้ผลที่ทำจริง พร้อมระบุรุ่นกล้อง firmware เวอร์ชันแพ็กเกจ และสิ่งที่ยังไม่ทดสอบ
- ลิงก์ดาวน์โหลด: ให้ตรงรุ่น พร้อมซอร์สและ checksum และผ่านการตรวจที่ค้างอยู่ก่อนประกาศว่าพร้อม
- ช่องทางรับเงิน: ตอนนี้ยังไม่เปิด หากจะเพิ่มภายหลังต้องระบุผู้รับ วัตถุประสงค์ และเงื่อนไขให้ชัดก่อน
- เครดิต: รักษาเครดิต Magic Lantern และใบอนุญาตของส่วนประกอบเดิม

ภาพที่เพิ่มใหม่ควรตรวจและลบ metadata ที่มีข้อมูลพิกัดหรือข้อมูลส่วนตัวก่อนนำเข้า Git ห้ามเก็บไฟล์ต้นฉบับที่มีข้อมูลเหล่านี้ใน branch สาธารณะ หากยังไม่ทราบบิลด์ในภาพ ไม่ควรระบุว่าเป็น v3r2 จากหน้าตาเพียงอย่างเดียว
